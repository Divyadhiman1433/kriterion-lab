# Security Policy

## Supported versions

Security fixes are applied to the latest version on the default branch.

## Reporting a vulnerability

Do not open a public issue for a vulnerability. Contact the repository owner privately through the email address associated with the GitHub account that publishes this project. Include a concise description, affected files or versions, reproduction steps, and the expected impact.

You should receive an acknowledgement within seven days. Please allow a reasonable remediation period before public disclosure.

## Scope

Relevant reports include dependency vulnerabilities, arbitrary file access, unsafe deserialization, leaked credentials, and deployment configuration that exposes sensitive data. Model accuracy concerns and methodological disagreements should use the normal issue tracker unless they reveal a security or privacy risk.

The application is an educational demonstration and is not intended for clinical decisions.
